# Seven-Day Launch Plan

This plan assumes the product page is ready, screenshots are available, license terms are finalized, and the downloadable ZIP has been reviewed.

## Day 1 - Publish And Announce

Goal: Make the product buyable and get the first qualified traffic.

Actions:

1. Publish the Gumroad product.
2. Verify the purchase flow with a test purchase if possible.
3. Publish or update the GitHub release.
4. Publish the product landing page.
5. Add the six-image marketplace gallery.
6. Post launch announcement on LinkedIn.
7. Post launch announcement on X/Twitter.
8. Post in one relevant founder/build-in-public community.
9. DM 10 warm contacts who build AI or internal tools.
10. Track all questions in a simple notes file.

Primary message:

> I launched a FastAPI + Next.js source-code kit for PDF ingestion workflows. It turns PDFs into Markdown, HTML, JSON, text, reports, extracted images, and ZIP packages using Marker locally.

## Day 2 - Developer Proof

Goal: Show that it is a real developer product.

Actions:

1. Post the FastAPI endpoint screenshot.
2. Post the structured JSON screenshot.
3. Share the validation commands that pass.
4. Write a short thread: "What is inside RelayWorks."
5. DM 10 AI developers who talk about RAG or document ingestion.
6. Ask 3 developers for objections to the listing.
7. Update FAQ if the same question appears twice.

Primary message:

> This is not a mockup. It includes FastAPI routes, background jobs, local job metadata, export files, package downloads, and a Next.js review workspace.

## Day 3 - Use Case Outreach

Goal: Find buyers with immediate document pain.

Actions:

1. Search LinkedIn for "RAG PDF", "knowledge base PDF", "document ingestion", and "internal tools AI".
2. Save 30 leads.
3. Send 15 concise personalized messages.
4. Post a screenshot of Markdown output.
5. Post a screenshot of the processing report.
6. Ask one agency owner what would make it usable for client work.
7. Add objections to the launch notes.

Outreach angle:

> Saw you building around PDFs/RAG. I just launched a source-code PDF ingestion kit that handles upload, Marker conversion, background jobs, Markdown/JSON exports, reports, and ZIP packages. Useful if you want a starting point instead of wiring the baseline yourself.

## Day 4 - Demo Day

Goal: Make the workflow tangible.

Actions:

1. Post the demo video if final.
2. If not, post a 4-screenshot carousel: goal selection, processing, complete, JSON.
3. Record a short install walkthrough if needed.
4. Offer 3 free live walkthrough calls to qualified buyers.
5. DM 10 agencies or consultants who sell AI automation.
6. Ask viewers what output format matters most.

Primary message:

> The core flow: upload PDF, select goal, background job runs, inspect Markdown/JSON/report/images, download complete package.

## Day 5 - Comparison And Positioning

Goal: Explain why this exists despite Marker, Unstructured, Docling, and Acrobat AI.

Actions:

1. Publish a comparison post using `07_COMPETITOR_COMPARISON.md`.
2. Emphasize that RelayWorks wraps a product workflow around local processing.
3. Post the download package screenshot.
4. Reply to comments with honest limitations.
5. DM 10 people who build internal tools.
6. Update listing copy if positioning is misunderstood.

Primary message:

> RelayWorks is not trying to replace parsing libraries or Acrobat. It is a source-owned app baseline around PDF ingestion: frontend, backend, jobs, outputs, reports, packages.

## Day 6 - Buyer Objection Handling

Goal: Convert interested but uncertain prospects.

Actions:

1. Review every question received.
2. Add the top 5 questions to the Gumroad FAQ.
3. Add one "Known limitations" section if missing.
4. Post a transparent limitations thread.
5. Offer launch discount reminder.
6. Follow up with everyone who clicked, replied, or asked a question.
7. Ask for one testimonial from any early buyer or reviewer.

Primary message:

> RelayWorks is PDF-first, local-first, and depends on Marker. It is for developers who want source code and a working baseline, not a hosted black-box extraction service.

## Day 7 - Close The Launch Window

Goal: Create urgency and capture learnings.

Actions:

1. Post final launch discount reminder.
2. Send follow-up to all warm leads.
3. Publish a short "what I learned from launch week" post.
4. Summarize objections and feature requests.
5. Decide whether to keep, raise, or simplify pricing.
6. Identify the strongest buyer segment from responses.
7. Plan next iteration based on buyer demand, not assumptions.

Primary message:

> Last day for launch pricing. If you are building PDF ingestion for RAG, knowledge bases, or internal tools, RelayWorks gives you a FastAPI + Next.js starting point with local processing and packaged outputs.
